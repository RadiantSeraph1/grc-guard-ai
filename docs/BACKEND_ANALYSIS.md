# Backend Analysis Design

## Endpoint
`POST /api/analysis/run`

## Inputs
- `question`: optional analyst question.
- `department`: optional department filter.
- `include_ai`: whether to call active AI provider or return local-only analysis.

## Output
- Metrics: readiness, risk pressure, failing controls, warning controls, open risks, failing assets, evidence, policies, connected integrations, RAG chunks.
- Control analysis: control status, department, evidence count, stale evidence count.
- Risk hotspots: open risks sorted by residual score.
- Recommended actions: deterministic remediation priorities.
- Citations: RAG chunks relevant to the question.
- AI summary: generated by active provider or local fallback.

## Analysis Logic
The backend joins app state across users, departments, controls, risks, assets, evidence, policies, integrations, and RAG chunks. It computes local posture first, then optionally asks the AI gateway to produce a concise executive interpretation.
